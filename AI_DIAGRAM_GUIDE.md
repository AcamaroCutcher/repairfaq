# RepairFAQ diagrams: a guide for AI models

This file is a brief for an AI model (for example a future Claude model) that will build richer versions of the
circuit diagrams in this archive: true 3D models, animations, simulations or interactive explainers. It explains
where the diagrams are, how they are written, what already exists, what is allowed, and what would be worth doing next.

Generated by `repairfaq_modern/guide.py` from the site's data. The counts below were correct when it was generated.

### A diagram record (`diagrams.json`)

A real record (the long `ascii` and `context` strings are shortened here):

```json
{
  "id": "4ba5c0ae2933",
  "page": "sam/laserhps.htm",
  "title": "Sam's Laser FAQ - HeNe Laser Power Supplies",
  "collection": "laser",
  "heading": "Basic HeNe Laser Power Supply Organization",
  "anchor": "hpscao1",
  "context": "… to be set by controlling the power input and/or selecting the ballast resistor.",
  "parts": [
    "resistor",
    "ground",
    "lamp/tube"
  ],
  "refs": [],
  "ascii": "         +----------+     +------------------+ HV+   Ballast…",
  "source": "https://www.repairfaq.org/sam/laserhps.htm#hpscao1",
  "also": [],
  "notice": "a68b901bcf",
  "notice_from": "parent"
}
```

| Field | Meaning |
|---|---|
| `id` | first 12 hex digits of the SHA-1 of the ASCII with all whitespace removed; stable across rebuilds |
| `page` | the page it appears on, relative to `archive/` |
| `collection` | `laser`, `sam`, `repair` or `other` |
| `heading`, `anchor` | nearest heading and nearest `<a name>` above it: open `archive/<page>#<anchor>` |
| `context` | up to 320 characters of the text just before the diagram |
| `parts`, `refs` | heuristic guesses: part types, and reference designators such as R1 or C4 |
| `ascii` | the diagram exactly as published, with tabs expanded and the common indent removed |
| `source` | the original URL on repairfaq.org |
| `notice`, `notice_from` | key into `notices.json`; `own` (the page's own notice), `parent` (the FAQ's main page) or `site` (site-wide terms) |
| `also` | other pages where the identical diagram appears |

Find diagrams with `jq`, for example all transformers in the laser FAQ:
`jq '.[] | select(.collection=="laser" and (.parts|index("transformer"))) | .heading' companion/data/diagrams.json`

## 3. How the ASCII is drawn

The diagrams use a fixed-width character grid, so a character cell is about twice as tall as it is wide.
These conventions are what `schematic.js` understands. Treat them as a starting point: Sam is consistent, but
contributors vary.

| Characters | Meaning |
|---|---|
| `-` `=` | horizontal wire (`=` is sometimes a double line or a switch contact bar) |
| <code>&#124;</code> | vertical wire. A <code>&#124;</code> interrupting a `----` run is usually a **crossing without a connection** |
| `+` | junction or corner. Three or four connected sides means a connection (drawn with a dot) |
| `.` `'` | rounded corners (`.--` at the top, `'--` at the bottom) |
| `*` | explicit connection dot |
| `o` | terminal, test point or connector pin. `o/ o` is a switch, `o==o` a jumper |
| `/\/\` | resistor drawn horizontally. A vertical resistor is `\` and `/` stacked |
| <code>_&#124;_</code> over `---` | capacitor plates, or ground when it's at the end of a wire. `-` under <code>_&#124;_</code> is ground |
| <code>&#124;&#124;</code>, <code>-&#124;&#124;-</code>, <code>-&#124; &#124;-</code> | capacitor drawn horizontally |
| <code>&gt;&#124;</code>, <code>&#124;&lt;</code>, <code>-&#124;&gt;&#124;-</code> | diode (the bar is the cathode) |
| <code>)&#124;&#124;(</code>, <code>)::(</code> | transformer: coils `(` `)` either side of a core (<code>&#124;&#124;</code> iron, `::` ferrite) |
| `)))` or `ooo` | inductor |
| <code>&#124;/</code> with <code>&#124;\</code> below | bipolar transistor (base on the left, the arrow side is the emitter) |
| `+----+` boxes | a module, IC, tube or sub-circuit. The label inside names it |
| `>` `<` `v` `^` on a wire | arrowheads (signal or current direction) |
| `[` `]` with a label | often a lamp, tube or connector |

Text sits on the same grid: component names (`R1`), values (`47K`, `.001uF, 2kV`), wire colors and notes.
Labels belong to the nearest part, usually the one immediately left, right or above.

## 4. What exists now

- **Animated 2D** (`schematic.js`). `parse(ascii)` classifies every cell, then produces segments, curves (corners and coil
  turns), junction dots, terminals, arrows, boxes, text runs and **nets**: connected wires grouped by union-find over
  segment endpoints. `toSVG(model)` draws one path per net, so hovering a wire highlights its whole net. Wires draw
  themselves in on scroll, and a dashed overlay animates current flow.
- **3D board** (`schematic3d.js`). The same model on a circuit board: copper wires tinted per net, crossings hop
  over, `+----+` boxes become translucent modules with their labels on top, and particles wander the nets as current.
  Coordinates: 0.5 world units per column, 1.0 per row.
- **3D HeNe laser** (`hero3d.js`): a hand-built tube with a cathode can, a capillary bore, HR and OC mirrors and a
  beam, labeled with figures from `archive/sam/laserhen.htm` and `laserhps.htm`.

Known limits: parts are drawn as their characters (a resistor is a zig-zag wire, not a component body). Labels are
not attached to parts. Nets are geometric, not electrical (a resistor's two sides currently share a net because
its zig-zag is drawn as wire). The heuristic diagram detector misses some diagrams and keeps a few ASCII tables.

## 5. Worked example

`4ba5c0ae2933`, "Basic HeNe Laser Power Supply Organization" (sam/laserhps.htm):

```
         +----------+     +------------------+ HV+   Ballast Resistance
  o------|          |-----| Starting Circuit |--------------/\/\----+
Input,   |  Main    |     +------------------+               Rb     |
AC line  |  Power   |                                               |
or DC    |  Supply  |     +-----------+   Tube- +-----------+ Tube+ |
  o------|          |-----| Regulator |----+----|-[        -|-------+
         +----------+ HV- +-----------+   _|_   +-----------+
                                           -      HeNe tube
```

An electrical reading, which is the kind of output a netlist extractor should produce:

- The **Main Power Supply** takes AC line or DC input from the two `o` terminals at the left.
- Its **HV+** output feeds the **Starting Circuit**. The output of that goes through the ballast resistor **Rb**
  to **Tube+**, the anode of the **HeNe tube**.
- **Tube-**, the cathode, connects to a node that is grounded (<code>_&#124;_</code> over `-`), and from there through the
  **Regulator** back to the supply's **HV-** return.
- Sam's text just before the diagram adds that the starting circuit may be omitted in a high-compliance design and
  that the regulator's low-side position is only one option.

## 6. Ideas for the next model

In rough order of value:

1. **Electrical netlists.** Recognize components (resistor, capacitor, diode, transistor, transformer, lamp, switch,
   fuse, tube), split nets at component pins, attach labels and values, and emit a netlist per diagram
   (SPICE or JSON). Validate against the text around the diagram.
2. **Real 3D components.** Replace the zig-zags with modeled parts: resistors with color bands from their values,
   electrolytic and film capacitors, diode bodies with cathode bands, transformer cores and windings, HeNe tubes like
   `hero3d.js`, CRTs, flybacks, magnetrons. Keep the board layout from the ASCII so the original stays recognizable.
3. **Simulated animation.** Run the netlists through a simulator (ngspice compiled to WebAssembly) and drive the
   current particles, glow and meters from real values. Let readers change component values and watch the result.
4. **Explainers.** Step-by-step animations for the classic topologies in the FAQs: voltage multipliers, ballast
   resistors, flyback converters, microwave-oven HV circuits, SMPS feedback loops, HeNe and argon power supplies.
5. **Image schematics.** Read the GIF and PDF schematics into the same record format.
6. **Accessibility.** Generate a text description of each circuit for screen readers, from the netlist.

Any of these is a new rendering of Sam's work. Present it next to the original ASCII, with the notice and the source
link, as section 1 requires.
